# 相關研究

## 1. 食品語言理解與結構化營養資料

自然語言飲食記錄需要辨識餐點中的食品實體、份量和烹調資訊，並將提及連結至可查詢的標準概念。食品 NLP 的重要基礎包括標註語料、食品 ontology 和實體正規化。FoodBase 以人工校訂食譜標註建立食品實體語料 [RW03]；其後的 FoodNER 以 BERT/BioBERT 微調食品實體辨識模型，涵蓋食品/非食品及不同語意類別 [RW04]。E.Care 食品實體連結研究則比較字串、傳統機器學習和深度 few-shot 方法，將食譜提及映射至食品知識庫概念 [RW06]。這些工作表明，食物名稱抽取與資料庫匹配是相關但不同的步驟，模型輸出亦依賴語料和知識資源是否涵蓋目標概念。

通用 LLM 也開始被測試於食品 NER/NEL。Ogrinc 等人以 ChatGPT 3.5/4 在食品摘要和食譜語料上進行零樣本實驗，評估實體抽取與 ontology 連結 [RW05]。然而，這些基準不是繁體中文餐點記錄，且抽取/連結表現不直接代表食物份量或營養數值正確。DietSense 擬使用 LLM 解析口語意圖並抽取欄位，但需由 schema 驗證、候選排序、來源檢索及必要的使用者澄清提供約束；辨識不確定時不能把模型補全當成已知事實。

## 2. 檢索增強生成與工具使用

RAG 將外部非參數化知識檢索與語言生成結合。Lewis 等人的基礎研究使用 Wikipedia 索引，在知識密集型問答、事實查核及文字生成任務上評估 RAG [RW01]。ReAct 則研究模型如何交錯產生推理和工具行動，以與外部知識庫或環境互動 [RW02]。兩者提供檢索與工具協作的通用方法背景，但都不是營養任務準確性或健康安全性的證據。

更直接相關的是 Yan 等人的 DietAI24，該系統使用多模態 LLM 辨識餐點照片，透過 RAG 檢索美國 FNDDS 營養資料，再估計食物代碼、份量與多種營養成分；研究以 ASA24 和 Nutrition5k 評估其影像工作流程 [RW08]。DietAI24 已展示 MLLM、RAG 與標準營養資料庫的整合，因此不能把此組合本身描述為 DietSense 的首創。其影像輸入、FNDDS 來源與資料集情境也和 DietSense 提案的繁體中文文字輸入、台灣混合料理及人工搜尋比較不同，故各自效果需以相應任務測試，不能互相外推。

2026 年的研究已直接處理飲食自由文字映射與估值。Lemay 等人以 ASA24/FooDB 與 NHANES/DFG2 配對資料比較傳統檢索、嵌入與 LLM 混合方法；NutriRAG 則以既有成人飲食日誌評估檢索增強分類 [RW16], [RW17]。Lawabni 等人以文字查詢和 NCC 資料評估多個 LLM 的能量/營養估值；Cao 等人以中國食物成分表評估中國食品，顯示文字估值在部分總體指標可用，但微量營養素及個別食品仍有差異 [RW19], [RW20]。FoodyLLM 另展示以領域對齊資料訓練食品營養模型的路徑 [RW18]。這些研究排除了「文字食品映射或中文食品 LLM 估值尚未被研究」的寬泛說法；各研究使用的資料庫、食品單位、描述形式和評估任務仍不能直接代表台灣混合菜的多輪澄清與來源可追溯記錄。

台灣情境亦有 Diabot-GPT-4o 影像飲食評估研究，以 57 名年輕成人及秤重紀錄驗證 714 張餐點影像 [RW21]。這是台灣 AI 飲食評估先例，但其影像輸入、參與者及任務與本提案的文字對話記錄不同，不能作為 DietSense 效能證據；本研究的新穎性應限定在待驗證的工作流程與對照設計，避免「台灣尚無 AI 飲食評估」主張。

## 3. 影像飲食評估、資料集與份量估算

Nutrition5k 提供約 5,000 份餐點的視覺資料、成分重量和營養標籤，支持以影像預測熱量與巨量營養素的研究 [RW07]。但該資料來自美國餐廳餐點，不能作為台灣飲食代表性資料。Ho 等人的影像飲食評估系統性回顧與統合分析納入 13 項研究、606 位參與者，指出影像評估相對參照方法的整體能量估計呈低報且異質性高 [RW09]。此結果支持對不同資料集、食物類型與參照方法分層檢驗，不支持對所有影像系統下相同結論。

份量工具亦有自己的驗證問題。Amoutzopoulos 等人的系統性回顧整理 542 種份量估算元素，指出高品質驗證研究有限，工具需依效率、目標族群和使用場域選擇 [RW10]。在自然語言或影像皆不充分時，份量不確定性會傳遞到後續營養換算。DietSense 因此規劃追問關鍵份量、保存單位及假設，或在沒有可靠參照時提供部分結果/安全降級；未校準的上下界不作為統計信賴區間。

## 4. 營養計算、能量需求與參照資料

營養資料庫提供標準食品項目和營養欄位，計算結果的可重現性取決於食品身份、食物狀態、份量單位、來源版本及公式均有明確記錄。依每 100 g 營養密度和已確認克數作線性縮放，可使計算流程可重算；然而，若候選食品不相符或份量假設有偏，確定性不會使估值變準。一般 Atwater 因子可作能量近似，但官方標示規則也容許特定食品因子及資料庫能量值，故模型必須保留來源提供的能量欄位定義 [D3]。

Mifflin–St Jeor 是由健康成人間接熱量測定資料推導的 REE 預測等式 [RW11]；由 REE 再乘活動係數得到 TDEE 仍是估算。National Academies 2023 能量 DRI 報告更新 Estimated Energy Requirement 方程，並指出自陳能量攝取仍可能有系統性測量誤差 [RW12]。這些工具適用範圍和人口背景不同，不能把公式輸出當成代謝實測或個人處方。台灣 HPA 的 DRI/每日飲食指南才是本地一般參考的優先來源；目前官方頁面提及第九版草案已完成預告，正式採用前應核對最新核定版本與族群適用性 [D2]。

飲食自我監測研究說明其作為行為介入組件的可能用途和評估限制。Raber 等人回顧 59 項成人過重/肥胖行為性減重介入研究，包含紙本、網站、手機和電話記錄；研究指出不同監測強度可能支持介入，但依從性指標不一致，監測使用量與結果的關係分析有限 [RW13]。這不能證明某個介面會降低記錄負擔。DietSense 應比較任務時間、完成率、追問回合、缺漏及主觀可用性，並將原規劃的 20 人、7 日研究界定為初步可行性評估，而非長期健康成效試驗。

## 5. 綜合定位與研究機會

既有研究已分別建立食品實體語料與連結方法、一般 RAG/Agent 工具使用方法、影像式營養估算資料集、份量工具評估及營養參照公式。DietAI24 更已把多模態 LLM、RAG 與 FNDDS 用於照片營養分析，故 DietSense 不以「首次整合 AI 與營養資料」作研究缺口。較窄且可測的機會，是在已存在的 free-text mapping、NutriRAG、LLM 文字營養估值、FoodyLLM 及台灣影像評估成果之上，檢驗繁體中文台灣混合料理的多輪文字日誌如何映射到適用資料、何時需要澄清，以及逐項來源與份量假設可追溯的工作流程，相較固定手動搜尋輸入流程在估算誤差、來源追溯、記錄時間、完成率和澄清負擔上有何差異。這是情境化的研究問題，不是聲稱尚無相關方法或台灣先例。

目前搜尋不是系統性回顧，也未直接涵蓋所有資料庫或商用產品，因此尚不能確定該任務是否為全領域未解問題。DietSense 的設計假設是：將語言理解和工具選擇交由 LLM，將營養數字交由有版本來源的資料與確定性計算，並以有限澄清和安全限制處理不充分輸入。此假設須由預先定義的資料集、固定 baseline、來源審核及可行性使用者研究檢驗，不構成已證實的效能結論。
