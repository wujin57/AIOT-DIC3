# 相關研究（一）：AI 技術

## 範圍與定位

本節回顧 DietSense 所需的自然語言食物理解、外部資料檢索、食物資訊抽取、影像營養估算及工具協作。這是依指定議題進行的敘述性範圍查核，不是系統性回顧；搜尋策略、資料庫存取情形和限制見 [literature-search-log.md](../research/literature-search-log.md)。本節不把一般 NLP/Agent 基準表現推論成營養任務效能。

## A. LLM 與飲食描述理解

飲食記錄涉及從自由文字辨識食物名稱、烹調狀態、份量、配料、時間及修正內容。食品領域早期方法以詞典、規則和標註語料為基礎。Popovski 等人建立 FoodBase，提供 1,000 篇食譜的人工校訂食品實體標記，並提出未經專家校訂的較大語料版本 [RW03]。Stojanov 等人的 FoodNER 對 FoodBase 及相關食品語意標籤微調 BERT/BioBERT，讓任務由「是否為食品」延伸到類別辨識 [RW04]。這類監督式方法可以輸出明確標籤，但依賴訓練語料、ontology 和標籤涵蓋；英文食譜語料並不能直接代表繁體中文口語或台灣混合菜。

食品辨識之後還需把文字提及連結到營養資料概念。Feher 等人以 E.Care knowledge base（664 個概念）及 468 篇食譜研究 few-shot food entity linking，並比較字串、傳統機器學習及深度模型 [RW06]。Ogrinc 等人以 ChatGPT 3.5/4 在 CafeteriaSA 與 CafeteriaFCD 執行零樣本食物 NER/NEL 評估；資料包含科學摘要與食譜，並將提及映射至 FoodOn、SNOMED CT 等資源 [RW05]。兩項研究都顯示食品實體正規化是一項獨立且依資料集與知識庫而異的任務。其語料、標籤慣例和語言與 DietSense 的使用情境不完全相同，且抽取/連結準確率本身不等於營養估值準確率。

2026 年已有更直接的飲食文字任務研究。NutriRAG 以飲食記錄 App 的自由文字資料建立檢索增強食品分類流程，並在 77 位成人的既有試驗記錄上評估分類 [RW17]；Lemay 等人以 ASA24-to-FooDB 和 NHANES-to-DFG2 標註集比較模糊字串、TF-IDF、embedding、LLM 與 hybrid ranking，並將 hybrid mapping 做成 FoodMapper [RW16]。另有文字提示估計能量和營養素、對照美國 NCC 資料庫的研究 [RW19]，以及以中國食物成分表評估 299 種中國食品的九個 LLM 研究 [RW20]。這些新成果直接涉及自由文字分類、資料庫匹配及純文字營養估值；因此不能再把「繁體中文文字輸入」概括成未被研究的能力。它們仍有不同資料庫、食品單位、食物描述及研究操作，沒有直接驗證 DietSense 的台灣混合餐對話、澄清/來源流程或固定手動輸入對照。

DietSense 因此把 LLM 視為對話解析和工作流程協調元件：先抽取欄位、保留使用者原文，再交由 schema 驗證、候選檢索與有限澄清處理。FoodMapper 和 NutriRAG 已說明文字食品匹配/分類可被專門評估；DietSense 的可檢驗定位是台灣複合餐描述、對話澄清、逐值來源與確定性加總的完整任務表現，而非宣稱「LLM 首次能處理文字飲食」。關鍵欄位不足或食物候選衝突時，不應由模型自行補造配方或營養數字。

## B. Retrieval-Augmented Generation 與來源追溯

Lewis 等人提出的 RAG 將參數化生成模型與非參數化檢索記憶結合，並在知識密集型 NLP 任務（例如開放式問答與事實查核）評估 [RW01]。此研究提供「生成前檢索外部內容」的技術基礎，但其知識庫是 Wikipedia，任務不是食物識別或營養估算。RAG 可使被檢索的材料可檢視，卻無法保證候選正確、來源版本適用或生成內容忠實；檢索錯誤和生成錯誤仍須獨立量測。

DietAI24 是與本專題定位密切相關的較新研究：Yan 等人將多模態 LLM、RAG 與美國 FNDDS 食物資料庫結合，用於食物照片的食物代碼、份量及營養估算，並在 ASA24 與 Nutrition5k 上比較基線 [RW08]。研究直接顯示「LLM + RAG + 標準營養資料」已存在於影像飲食評估領域，因此 DietSense 不主張技術組合本身首創。DietAI24 的輸入以照片為主，所用 FNDDS 反映美國食品環境；它不能替代台灣繁體中文文字記錄、在地食物來源或澄清工作流程的任務驗證。其結果也不證明另一個資料庫、語言或介面會達成相同效果。

2026 年發表的 FoodyLLM 以 225,000 組任務化 QA 資料訓練食品領域模型，評估食譜營養估算、營養標示分類及 ontology-based entity linking [RW18]。這項工作進一步證明食品領域專用 LLM 已有研究，不應將通用模型加結構資料描述為唯一可行路徑。DietSense 的提案不是訓練另一個領域模型，而是採用可替換 LLM 作語言/流程介面，並將營養數值交由有版本來源的結構化項目及公式計算；兩種架構需依同一任務基準比較才可判定效用。

DietSense 的設計把資料來源 ID、版本、欄位、食物狀態和計算假設保存在營養紀錄中。來源追溯是可驗證的資料工程性質，不是估值準確的保證。評估需分別報告來源欄位完整率、錯誤候選接受率、無來源數值率、營養誤差及失敗降級行為。

## C. Food NER 與食品資訊抽取

FoodBase、FoodNER、CafeteriaSA/FCD 及 E.Care 資源構成食品 NER、語意正規化及 entity linking 的代表性工作 [RW03]–[RW06]。它們顯示食品實體抽取不只是一般命名實體辨識：同一提及可能須映射至分類本體、膳食資料庫代碼或配方成分；映射的可用度受語料、ontology 和領域標準影響。Ogrinc 等人的零樣本 ChatGPT 評估亦提醒，通用模型可被測試於食品 NER/NEL，但研究語料和任務定義必須與部署任務對齊 [RW05]。

現有代表語料以英語食譜、科學摘要或歐洲/國際食品語意資源為主；本次搜尋未找到足以量化繁體中文台灣混合菜覆蓋的完整基準。這是搜尋範圍內尚待確認的資料缺口，而非全領域不存在相關工作之證明。DietSense 擬建立含口語別名、組合餐、份量及拒答/缺資料案例的專題測試集，並分開評估 dish-level、ingredient-level 匹配和候選覆蓋。

## D. 食物影像辨識與多模態飲食評估

Thames 等人提出 Nutrition5k：約 5,000 份餐點的影片/影像、深度資訊、成分重量及營養標籤，並展示視覺模型預測餐點熱量和宏量營養素的基準 [RW07]。該資料集支持影像營養估算研究，但由美國 Google 餐廳情境採集，並非台灣飲食代表樣本。Ho 等人的影像飲食評估系統性回顧與統合分析納入 13 項研究、606 位參與者；整體能量攝取相對參照方法呈低報，異質性高 [RW09]。合併結果不代表每一模型固定有相同偏差，也凸顯影像估值需與人群、參照方法和食物型態一起報告。

DietAI24 進一步以 MLLM 辨識照片、以 RAG 檢索 FNDDS、計算份量及 65 項營養成分，在兩個美國資料集與既有基線比較 [RW08]。該研究本身在討論中指出其視覺識別、份量誤差、資料庫地域性與使用者行為等限制。其存在使 DietSense 的差異應界定在文字優先、繁體中文台灣餐點描述、澄清負擔和對話式日誌任務，而非宣稱前所未有的 RAG 營養架構。Stage 3 將照片辨識定位為可選擴充，不是 MVP 必要輸入路徑。

## E. AI Agent 工具使用與結構化流程

Yao 等人的 ReAct 研究將語言模型的推理軌跡與外部行動交錯，在問答、事實查核及互動環境任務中研究工具使用 [RW02]。這提供 Agent 調用外部工具及應對觀察結果的通用方法背景，但不等同於飲食 Agent 的安全性或可靠性證據。DietSense 的八模組流程更要求明確介面、型別檢查、有限追問、錯誤分支、計算函式和安全決策；這些屬 Stage 3 的工程設計，不是 ReAct 論文已驗證的營養功能。

## AI 文獻綜合

代表研究已涵蓋食品 NER/NEL、free-text 資料庫映射、RAG 分類、領域微調、文字估營養、影像多模態估值和 Agent 工具使用；因此本研究不能宣稱「文字型食品資料映射未被研究」或「LLM+RAG+資料庫尚無實作」。近年研究仍使用不同資料源、國家菜色、食品單位、輸入方式與 outcome，尚未直接替代 DietSense 對台灣混合菜自然語言日誌的逐值來源、澄清負擔及固定手動搜尋比較。可測的問題是 DietSense 具體流程在預先指定資料與對照條件下呈現何種誤差、來源追溯、時間、完成率和追問負擔。由於搜尋並非系統性回顧，這是 provisional task positioning，不是全領域 novelty 結論。
