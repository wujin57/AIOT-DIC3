# DietSense 評估計畫

本文件把原提案的 500 筆台灣食物描述、對照基線、誤差/時間/SUS 指標，以及 20 位參與者、7 天使用研究整理為可預先登錄的研究計畫。這些均為**未來提案**；尚未招募、收集資料或得出結果。所有候選門檻須在 pilot 和標註方案確定後預先鎖定。

## 1. 研究問題與 estimand

### RQ1：食物與營養估值

在含多種台灣餐點的固定測試集上，DietSense 對食物身份、熱量和可取得巨量營養素的估算表現如何？主要 estimand 是每筆可評估餐點的 absolute calorie error 相對標準參照，以及在預先指定 ±20% 容許帶內的比例；分開報告不輸出估值/拒絕估算的案例，避免只評估容易案例。

### RQ2：澄清/追溯和失敗處理

關鍵欄位缺失、資料庫弱匹配或無候選時，系統是否提出可理解澄清、保留來源並避免無依據數值？估計來源追溯率、有效澄清率、無答案/錯誤接受率、fallback 類別和任務完成情形。

### RQ3：記錄流程可行性

與固定、記錄版本的 manual-search-and-entry baseline 相比，DietSense 的餐點記錄耗時、完成率、澄清負擔和主觀可用性如何？短期 20 人研究為可行性/操作性評估，不是健康療效或優越性試驗。

## 2. 500 筆資料集計畫

### 2.1 範圍與抽樣框

單位為一則繁體中文餐點描述及其可評分的食物/份量/營養標籤。文字以真實或自然口語描述為主；合成/模板增補樣本須分層標示，不得冒充自然使用者樣本。保留原始描述來源、同意/授權依據、擷取日期、語言、品項類型及版本。

建議在抽樣框內分層納入：

1. 單一/包裝食品（品牌、容量、標示或單位清楚）；
2. 台灣便當與主食組合；
3. 湯麵/湯品（含湯量、配料/麵量不確定）；
4. 夜市/街頭混合菜（如雞排、蚵仔煎、臭豆腐、珍珠飲品）；
5. 家常/自製混合菜或地方食譜；
6. 刻意缺資訊、歧義、錯別名、矛盾份量、無來源候選等失敗/安全案例。

類別比例及每類數量需在來源盤點後決定並註冊。分層抽樣目的為涵蓋系統能力範圍，不代表能推估台灣人口飲食盛行率。地區、店家/配方、季節、品牌需盡量記錄，以便評估群聚和資料洩漏。

### 2.2 參照營養標籤

每筆標籤記錄參照等級：

- **A：包裝標示/官方資料源項目**，且產品 ID、份量及版本可核對；
- **B：標準化食譜 + 原料秤重/可食部記錄 + 對應營養資料源**，明列生熟轉換和烹調損失假設；
- **C：研究員採集的店家/現成餐點**，以餐前/剩食重量、成分拆解及可用成分來源估算，標明無法量測的油、醬或配方變異；
- **D：無法建立充分參照**，只評估系統是否安全降級/追問，不計入數值誤差主分析。

參照值並非無誤差真值。標籤記錄 nutrient source、source ID/version、ingredient/portion weight、測量設備/程序、估算層級、參照不確定來源及營養專業審核狀態。若以食譜資料庫估算，需標為 calculated reference，不與 laboratory-analyzed value 混為一談。

### 2.3 標註流程與一致性

1. 先定義 codebook：食物名稱、別名、混合菜成分、份量/單位、烹調、剩食、可評分性、資料源匹配和未知值代碼。
2. 兩位標註者獨立標註全部或預先抽定的雙標註子集；若人力不能雙標全部，需在資料切分前定明比例和抽樣方式。
3. 兩位受訓標註者記錄原文可辨識欄位，不看模型預測；營養師/合格專家裁決爭議參照值和混合菜配方規則。
4. 在正式標註前用獨立 pilot 校訂 codebook；pilot 項目不併入測試集，除非重新盲標並記錄版本。
5. 類別標註報告 Cohen’s κ（兩位標註者；類別不平衡時同報原始一致率及適當補充指標）；連續量值報告 ICC 指定模型/一致性定義及 Bland–Altman 差異分析。不能只報相關係數。
6. 爭議逐項 adjudication，保留原始獨立標註與裁決後值；不得只保存裁決答案而失去一致性分析。

### 2.4 資料切分與污染控制

在系統調參之前按餐點/配方/店家/品牌群組切分，避免同一配方變體或複製描述跨 train/dev/test。切分比例須根據實際分層樣本量預先註冊；若測試集過小，報告置信/不確定範圍與限制，不以整數百分比誇大。測試標籤不提供給 LLM/RAG 索引；所有參與系統的來源快照和提示版本固定。

## 3. Baseline 與比較條件

- **主要 baseline：** 一個指定版本的手動搜尋與輸入流程（需選定可合法使用的 nutrition-tracking app 或固定來源頁面），使用相同題目、來源資料及作業說明。記錄 app/來源名稱、版本、測試日期、搜尋條件和是否可保存食譜。
- **分析 baseline：** 來源直接查表 + 研究員手動套用同一營養公式，用於區分資料來源/份量標準誤差與對話/檢索錯誤。
- **系統消融（若資源允許）：** (a) parser + deterministic calculation，不做澄清；(b) 完整 retrieval/clarification/calculation；(c) LLM-only 僅作錯誤分析，不允許成為產品輸出。消融不是必要時可不執行，但需記為偏離 protocol。

Baseline 的資料源、portion handling、操作熟練程度與任務時間會影響比較，需報告並限制外推；不能只比較模型輸出而不統一 reference/餐點任務。

## 4. 指標定義與分析

| 面向 | 指標/定義 | 分析/報告方式 |
|---|---|---|
| 食物識別 | Exact normalized top-1 accuracy；混合菜另報 dish-level accuracy、ingredient precision/recall/F1；候選覆蓋率 = 有至少一筆有效候選數 / 可評估輸入數 | 按食物類別、品牌/非品牌、單一/混合菜分層；D 類不可評估項不列入營養 accuracy，另報拒絕/降級正確性 |
| 熱量誤差 | 每項 `absolute error = |estimated_kcal − reference_kcal|`；報 MAE、median absolute error、IQR；若 reference > 0，報 `absolute percentage error = |estimate-reference|/reference × 100%` | 依系統是否有答案同時報 coverage；±10%、±20% 帶內比例為 `(reference > 0 且 APE <= 0.10/0.20)` 的可評估樣本數 / 參照可評估數；0 reference 不計 APE，單報 kcal error |
| 範圍品質 | `point estimate` error；range coverage = reference 是否位於 `[low, high]`；平均 range width = high-low | 只有存在 evidence-bounded range 的 case 評估；這是測試集經驗覆蓋率，不可稱置信區間覆蓋率，需另行校準/設計才可作概率解釋 |
| Macronutrients | Protein/carbohydrate/fat/fiber 各自 MAE g；若來源缺欄位，分母只納入可評估欄位並另報 completeness | 不把 energy-to-macro 換算當實測值；macro ratio 僅在所有指定欄位可用且分母 >0 時報告 |
| 完成時間 | 從顯示任務起到提交/放棄的秒數；含查詢、澄清及修正 | 報中位數/IQR；分別報成功與放棄任務；預先決定 outlier handling，不刪除長時間任務而不說明 |
| 澄清負擔 | 每筆平均/中位澄清回合；至少一問比例；每次成功記錄耗時；skip/abandon rate | 按任務缺欄位類型分層；人工問題與模型問題使用相同 turn 定義 |
| 來源追溯 | 數值欄位具有有效 source ID/version/field lineage 的比例；錯誤來源接受率；失效來源/無來源卻輸出數值率 | 以人工 audit source record；無來源數值率作 safety-critical error 單獨列出 |
| 失敗處理 | timeout、無候選、資料衝突、schema 失敗、計算拒絕、安全攔截的發生率及正確 fallback 比例 | 報各分支的分母、重試數、成功恢復率；不得將拒答合理失敗計入錯誤估值 |
| 任務完成 | 使用者完成/提交的有效記錄數 ÷ 被分派任務數 | 分別報每條件及信賴區間；放棄不從分母移除 |
| 易用性 | System Usability Scale (SUS)：標準 10 題、每題 1–5 分，依標準計分後轉 0–100 | 描述平均/SD/中位數與分布；SUS 分數不是百分比、也不直接證明營養準確或臨床效益 |

### 統計分析

預先指定一項主要 outcome（建議固定測試集 calorie MAE 或 ±20% 比例擇一；pilot 後鎖定），其他列為次要/探索結果。對同一餐點/同一參與者的配對流程用 paired difference 或適用的混合效應模型；計算 95% CI 僅用於統計結果的不確定性表達，並明確說明計算方法。偏態時間/誤差可報中位數/IQR，必要時用 bootstrap CI。對餐點/店家群聚採 cluster-aware bootstrap 或混合模型；多重次要比較標示探索性。缺失/不可評估案例及拒答以 flow diagram 報告，不以完整案例分析隱去。分析程式/參數與排除規則需預先固定。

## 5. 20 人、7 天可行性使用者研究

### 設計建議

- 目標為流程可行性、日常記錄負擔、錯誤類型與可用性，不測減重或健康療效。
- 擬招募 20 位成年自願參與者；樣本數是原提案規劃，不是 power calculation。招募條件、排除標準與族群組成待倫理審查及可行性確認。
- 7 日內使用 DietSense 與預先指定 baseline 記錄一致的任務/餐點。若採 within-subject，需以平衡順序/任務分派降低學習和順序效應；若自然餐點無法交叉分派，另加標準任務集作公平比較，兩類分析分開。
- 使用者可選擇不輸入敏感資料、跳過熱量數字或退出。研究不得要求減重、限制飲食或依建議改變食物攝取。
- 任務結束填 SUS 和短問卷/訪談；將可識別資料與飲食紀錄分開保存。

### 主要可行性結果

招募/同意比例、七日完成與退出情形、每日記錄數、任務完成率、可用性問題、SUS 分布、錯誤/安全事件、系統可用率及延遲分布。探索性比較時間、估算誤差、澄清數和 completion rate，報配對差異與寬不確定範圍，不作顯著性宣傳或普遍化結論。

### 倫理、同意與隱私

開始招募前完成校方倫理/IRB 或適用審查，取得知情同意並說明資料類型、第三方模型處理、保存期限、存取人員、撤回方式、資料刪除及結果發表方式。蒐集最小必要資訊；不在第三方 API 傳送姓名、email、地點或非必要健康資料；執行前核實模型提供者的資料使用/保留條款。安全事件須有停止流程與指定研究聯絡人。未通過適用審查不得開始研究。

## 6. 候選目標與樣本數限制

原 Proposal/PPT 提過「±20% 誤差內 >85%」「記錄時間縮短 60%」「SUS >70」等候選目標。本文件不把它們設為已驗收門檻。要保留為正式成功標準，需在 pilot 前說明：測試集可評估項目、reference 不確定性、baseline 版本、主要 estimand、樣本數/精度理由、缺失案例處理。建議先以 pilot 估計變異與流程完成率，再鎖定判定標準；若不適合，預註冊修訂依據。

20 名參與者、7 天觀察易受自我選擇、短期新奇效應、使用者熟悉度、餐點頻率和漏記偏差影響；不足以支持人口推論、subgroup 效果、體重改變、飲食行為因果、臨床安全性或 superiority claim。500 筆資料若類別/店家涵蓋不均，也不等於代表性全台食物資料集。
